  0.8 — Animation-clock & concurrency                                                                                                                                                                                
                                                                  
  Single clock: AnimationController (Animation/AnimationController.swift, owned by V2RootViewController line 42-43, passed into TimelineCanvas). K8 keystone: per-canvas instance identity; one CADisplayLink for the
   app.                                   

  Mechanism: animators register with the controller as subscribers via AnimatorProviding. Per-tick callbacks happen on main-thread via the display link.                                                             
                                          
  Pinch driver mechanism: NO display link — the pinch is RECOGNIZER-driven. Each .changed callback fires from UIKit's gesture recognizer event loop, on main thread, and writes synchronously. The recognizer's      
  frequency depends on touch event delivery (typically 60-120Hz on iPhone 16's ProMotion display).                                                                                                                   
  
  Tap-morph driver: MorphChoreographer.engage constructs a CurveAnimator<CGFloat> that subscribes to the AnimationController; ticks every display-link frame; calls apply which writes contentHost.transform +       
  heightC.constant + camera per-tick. Synchronous main-thread.    
                                                                                                                                                                                                                     
  Reveal driver: RevealCoordinator.runRevealChoreography uses UIViewPropertyAnimator (three of them: blurFadeIn, crossFade, blurFadeOut) for the blur+alpha animations. These are UIKit-driven animators, not the    
  AnimationController's display link. They co-exist by writing to DIFFERENT properties (blur.alpha, chatVC.view.alpha, canvas.alpha) than the AnimationController writes (cell.heightConstraint.constant via
  animators, contentHost.layer.transform via MorphChoreographer).                                                                                                                                                    
                                                                                                                                                                                                                     
  CATransaction.withSuppressedActions discipline (K4): every per-frame layer-property mutation site wraps. Verified in: TimelineCanvas pinch (line 1089, 1142, 1284), MorphChoreographer.apply (line 79), CellView
  (line 187, 282, 1089), RevealCoordinator.performAtomicAlphaSwap (line 214). The wave-13 commit e038da3 explicitly notes "CATransaction.withSuppressedActions wrap on applyMorphTickCameraWrite (fixes              
  implicit-animation leak per §45.4)" — they have HISTORICALLY missed the wrap (Atlas #1 Wave 4's exact finding pattern in real-app code).
                                                                                                                                                                                                                     
  Atlas #1's per-frame model coexistence verdict: The sandbox's ScalingSurface.subscribe(_:) pattern with N internal subscribers IS structurally compatible with the real app's animator-subscriber model on the
  AnimationController. The seam is the same: a single scalar drives N consumers. But the real app drives MULTIPLE actuators per tick (heightConstraint, contentHost.transform, camera, cell setCamera) from          
  MorphChoreographer.apply — these would need to be reframed as p-curve consumers if the sandbox's curve set replaces the current applier set.
                                                                                                                                                                                                                     
  Concurrency: All UI work is @MainActor. The 9S contract per CLAUDE.md §2.6 is respected: L1 (Animation/) is @MainActor; L2 (DesignSystem/Models/Tuning/Geometry + MorphTokens) is Sendable value types; L3
  (Conversation/Timeline + ChatBody + Data) is @MainActor; L4 (MorphChoreographer + RevealCoordinator + RevealBlurOverlay) is @MainActor; L5 (App/) is @MainActor. No background-thread work in the transition path.
